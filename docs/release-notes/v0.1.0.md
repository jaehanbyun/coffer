# Coffer 0.1.0 Production Candidate Release Notes

- Promotion status: blocked
- Release status: not released
- Updated: 2026-07-28

## Scope

Coffer 0.1.0 is the first planned operator-local production candidate for the
OpenStack-native OCI Registry service. Its intended release surface includes
the Coffer API, token service, quota edge, authenticated reconciler,
a qualified CNCF Distribution data plane, OpenStackClient commands, Horizon
dashboard, Skyline Console pages, and the companion Kolla-Ansible role.

## Current Boundary

This is not a released or production-qualified version. Ledger v1 remains
fail-closed at zero passed, one blocked, and nine pending gates. The additive
ledger v2 reports:

- Registry core: `blocked`;
- storage backend: `pending`;
- RGW and Barbican KMS: `blocked`;
- Horizon: `blocked`;
- Skyline: `blocked`; and
- Referrers: `pending`.

The current result has zero qualified profiles and
`production_candidate=false`. Distribution, Ceph Tentacle, and
`oslo.messaging` remain explicitly blocked in the scopes that consume them;
no independent v2 scope evidence has been accepted.

The retained Horizon/Skyline preview and all local fixtures are excluded from
production evidence.

ADR 0018 no longer requires an official upstream release as the only possible
provider lineage. A signed official release, approved vendor backport, or
Coffer-maintained minimal patch may qualify only after exact catalog
admission, immutable provenance, independent rebuild where required, the same
security/protocol/runtime threshold, current support, upstream submission,
and bounded retirement obligations all pass. No such provider is currently
qualified by the production policy.

## Required Before Release

- Change `Promotion status` to `production-candidate` only after Registry core
  independently qualifies against one admitted immutable provider lineage.
- Do not describe the service as deployable until a compatible selected
  storage profile also qualifies. Require RGW/Barbican KMS, Horizon, Skyline,
  and Referrers only for release profiles that enable them.
- Record the exact signed source tag or patch lineage, image digests, SBOM,
  provenance, vulnerability attestations, support matrix, upstream mapping,
  replacement deadline, and upgrade compatibility.
- Complete the independent operator review, repository regression, secret
  scan, documentation checks, rollback ownership, and zero-residue audit.
- Recompile the source-bound v2 scope results and ledger. Require
  `production_candidate=true` and every selected deployment combination
  constraint to be true.

Official Kolla or OpenStack upstream inclusion remains a later governance
phase and is not part of this release.
